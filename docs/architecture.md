# 架构说明

## 分层

- `IrisQuickQuery.Core`：领域定义、SQL 模板编译、安全校验、配置校验、运行上下文和串行调度器，不依赖 WPF 或 ODBC。
- `IrisQuickQuery.Infrastructure`：System.Data.Odbc、SQLite、DPAPI、注册表驱动/DSN 检测、配置包和无患者值执行日志。
- `IrisQuickQuery.App`：WPF/MVVM、现代浅色主题、动态字段卡片、列表与诊断、元素/规则/连接页面。
- `IrisQuickQuery.Core.Tests`：核心、存储、安全边界和 WPF STA 冒烟测试。

## 收敛模型

规则是否就绪只由其全部输入元素是否存在、非空且无冲突决定。调度器对 `规则 ID + 规范化输入值` 生成指纹，同一运行中每个指纹只执行一次；输入变化后可产生新指纹并重跑。因此配置顺序不参与语义，双向互查形成的循环也能稳定结束。

每个派生值保存来源 token 与上游依赖 token。列表更换选中行时，旧 selection token 及所有依赖它的值、执行记录和列表结果会被撤销，再从新行恢复调度。

## 安全边界

1. 配置校验与 ODBC 执行器都拒绝非 SELECT、分号、多语句及 DML/DDL/CALL。
2. 元素占位符只在 SQL 正常文本中解析，字符串和注释内的 `{{...}}` 不替换。
3. 参数按出现顺序创建强类型 ODBC `?` 参数。
4. IRIS 账号必须由服务器侧限制为只读；这是防止 SELECT 内有副作用函数或校验绕过的最终边界。
5. 快捷查询患者值只存在于 `RunContext` 和 WPF ViewModel 内存，不进入持久化接口。规则测试参数是明确例外，按规则 ID 使用当前 Windows 用户 DPAPI 加密后存入设置表，不进入日志、规则包或配置快照。

## 配置保存、升级与元素改名

- 安装升级沿用 `%LocalAppData%\IrisQuickQuery\config.db`，版本变化时先生成 SQLite 在线备份。
- 当前配置使用 SQLite 单例记录，每次保存进行原位覆盖，不再创建草稿、活动版或配置版本。
- 旧版快照表只作为升级迁移来源：首次迁移选择最后保存的旧配置，备份数据库并写入单例记录；确认成功后清空旧记录，后续不再向旧表新增数据。
- 元素 key 的变化通过元素固定 `Guid` 识别，只改写 SQL 正常文本中的 `{{key}}` 占位符及输出映射；字符串常量和注释不处理。

## 已知外部阻塞

- 当前机器注册表中没有检测到 64 位或 32 位 IRIS ODBC35，无法在本环境完成 IRIS 2023 真实连接、TLS 协商与命令取消验证。
- TLS 配置存在并不等于已经成功协商；驱动无法提供证据时，界面保持“未验证”。
- Inno Setup 6 是否存在由发布机器决定；没有时仍可生成完整 self-contained 发布目录。

# IRIS 快捷查询：长期产品要求与不可破坏约束

状态：当前有效  
基准版本：1.0.19
最后整理：2026-08-20

本文是本项目长期产品要求的集中记录。除非用户明确改变某项决定，否则后续开发、升级和打包均不得破坏本文中的“必须”要求。用户确认新要求后，应在同一次修改中同步更新本文，避免代码与文档长期分叉。

## 1. 产品边界

- 必须是 Windows 10/11 64 位单机桌面程序，当前技术栈为 WPF / .NET 8。
- 面向医院运维人员，通过全局业务元素和 SQL 规则完成 IRIS 数据的只读快捷查询。
- 应用只允许参数化的单条 `SELECT`，或最终语句为 `SELECT` 的 CTE；不得执行 DML、DDL、`CALL` 或多语句 SQL。
- 所有元素输入必须转换为 ODBC `?` 参数，严禁把患者输入拼接进 SQL。
- 数据库账号必须由服务器端限制为只读；客户端校验不能代替数据库权限。
- 不捆绑 InterSystems IRIS ODBC 驱动，由医院 IT 单独安装官方 64 位驱动。
- 当前产品边界不包含查询历史、快捷查询患者数据持久化、数据库写入和自动更新。查询入口测试区的加密测试参数是唯一明确例外。

## 2. 安装、升级与用户数据保护

### 2.1 程序文件与用户数据必须分离

- 安装目录为 `%LocalAppData%\Programs\IrisQuickQuery`，新版本可以覆盖这里的程序文件。
- 用户数据目录固定为 `%LocalAppData%\IrisQuickQuery`，不得放进安装目录：
  - `config.db`：当前全局元素、查询对象、查询入口、可执行规则、连接配置、DPAPI 加密密码、按入口加密的测试参数和其他设置。
  - `Logs`：不含患者值的执行元数据。
  - `Backups`：升级时生成的 SQLite 在线备份。
- 安装器的 `AppId` 和用户数据目录不得随版本变化，否则会造成重复安装或读取不到旧配置。

### 2.2 新版本必须保留的内容

覆盖安装或版本升级时，必须保留：

- 用户新增、删除、改名或调整过的全部全局元素及其固定 `Guid`。
- 用户配置的全部查询对象、查询入口、参数化 SQL、输出映射和启用状态；入口的固定运行 `Guid` 必须保留，以便继续关联已加密保存的测试参数。
- 当前配置；升级不能把它替换为程序自带默认配置。
- IRIS 驱动/DSN、主机、端口、Namespace、用户名、TLS 配置名等连接设置。
- 由当前 Windows 用户 DPAPI 加密保存的数据库密码。
- 由当前 Windows 用户 DPAPI 加密保存的查询入口测试参数。
- 快捷查询条件中已选择的全局元素固定 `Guid` 及排列顺序（不含任何患者值）。
- 已有日志和备份文件。

允许新版本更新数据库结构或内部版本标记，但迁移必须无损，不得以“初始化”为理由覆盖上述用户内容。

### 2.3 升级启动规则

- 检测到应用版本变化时，必须先把现有 `config.db` 在线备份到 `Backups`。
- 只有数据库中完全不存在当前配置和任何可迁移的旧配置时，才允许创建一份空白当前配置；新电脑或全新 Windows 用户首次运行时不得预置任何全局元素或 SQL 规则。
- “新环境空白”只适用于确实没有历史数据的首次运行。覆盖安装、升级、修复活动标记或迁移旧结构时，均不得以清空默认项为由删除或覆盖用户已有的全局元素、SQL 规则和连接配置。
- 从旧版“活动配置 + 草稿”结构升级时，必须把用户最后保存的配置迁移为唯一当前配置；不得因活动标记异常或默认配置误启用而覆盖用户较新的内容。
- 旧版配置记录只允许作为无损迁移来源；迁移前必须先备份数据库，成功写入唯一当前配置后清理旧版本记录。新版本不得继续创建配置版本或记录版本差异。
- 正常升级和卸载均不得主动删除 `%LocalAppData%\IrisQuickQuery`。如果将来增加“清除用户数据”功能，必须是单独、明确确认的操作，不能默认勾选。

### 2.4 免安装绿色版

- 每个正式版本允许同时提供 self-contained x64 绿色版 ZIP，解压后直接运行 `IrisQuickQuery.exe`，不要求安装 .NET，不创建卸载项。
- 绿色版与同版本安装包必须使用同一套程序二进制文件和相同内部版本号。
- 绿色版只能包含程序文件和使用说明，不得打包 `config.db`、`Logs`、`Backups`、密码、连接配置、SQL 测试参数或任何患者数据。
- 即使从绿色版目录运行，用户数据仍固定保存在 `%LocalAppData%\IrisQuickQuery`；同一电脑、同一 Windows 用户下与安装版共用已有配置，替换绿色版程序目录不得影响用户数据。
- 复制到另一台电脑或另一 Windows 用户时，不得假设 DPAPI 加密密码可以迁移，必须提示用户重新配置连接并输入密码。
- 绿色版不捆绑 IRIS ODBC 驱动；目标电脑仍必须由医院 IT 安装官方 64 位驱动。

## 3. 隐私与安全边界

- 快捷查询页面的患者输入值、SQL 派生值、查询结果集和列表选中结果只允许存在于运行内存。
- 查询入口测试参数是唯一持久化例外：必须按入口固定运行 ID 使用当前 Windows 用户范围的 DPAPI 加密后保存在本地；不得以明文保存。
- 除上述加密测试参数外，患者数据不得写入 SQLite、日志、规则包、配置导出或其他持久化文件。
- 日志只能记录排障所需的规则 ID、状态、耗时、行数和错误类别，不记录 SQL 参数值或结果值。
- `.irisqconfig` 规则包可以包含 SQL 模板、规则设置、输出映射，以及这些规则通过 SQL 参数或输出映射实际引用的全局元素定义；不得包含无关全局元素、服务器地址、用户名、密码、测试参数或患者数据。
- 密码只能使用 Windows 当前用户范围的 DPAPI 加密后保存；界面不得回显明文密码。

## 4. 配置保存语义

- 配置只保留一份“当前配置”，不提供草稿、整版启用、配置版本或版本回退。
- 元素配置页和 SQL 查询对象页右下角只显示一个“保存”按钮；不显示“重新加载活动版”“保存草稿”或“校验并整版启用”。
- 点击“保存”时必须先提交表格当前正在编辑的单元格和整行，再进行静态配置校验；校验通过后原子覆盖当前配置，并立即用于后续查询。
- 配置保存必须串行执行，快速重复点击不能并发写坏配置数据库。
- 查询入口的当前连接测试继续保留，用于配置者主动确认组合后的 SQL、参数和输出映射；它不再是保存配置的前置门槛。
- 修改 SQL 逻辑、元素类型或其他会改变查询语义的配置后，建议重新测试受影响规则。
- 保存成功后，当前配置页面只显示“配置已保存。”，不再把受控循环等警告追加在成功提示后；元素页和 SQL 查询对象页的提示状态必须彼此隔离，不能跨页面显示。
- 元素页和 SQL 查询对象页的底部提示区及保存按钮必须使用固定高度，长提示只能在当前提示区内截断显示，不能挤压上方列表或拉伸保存按钮。
- 全局元素通过固定 `Guid` 识别身份。修改全局元素名称/key 并点击“保存”时，必须自动同步：
  - 所有 SQL 正常文本中的 `{{旧名称}}` 占位符。
  - 所有输出映射中的旧元素名称。
  - SQL 字符串常量和注释中的同名文本不得改写。
- 仅进行全局元素改名时，已有规则应保持可直接查询，不要求用户逐条手工重新改写 SQL。

## 5. SQL 查询对象页面

### 5.0 查询对象与查询入口

- 用户配置层必须以“查询对象 + 查询入口”组织，不再要求用户为同一数据来源的不同筛选方式复制完整 SQL 和输出映射。
- 一个查询对象包含：对象名称、公共 `SELECT/FROM` SQL、公共输出映射、启用状态，以及一个或多个查询入口。
- 每个查询入口包含：入口名称、参数化筛选条件、单条/列表结果方式、是否 `TOP 1`、排序、启用状态、超时和最大行数。
- 公共 SQL 不填写入口专属的 `WHERE`、`ORDER BY`、`TOP 1` 或输入元素占位符；筛选条件不重复填写 `WHERE`，排序不重复填写 `ORDER BY`。
- 每个入口在运行时编译为现有安全执行规则，因此必须继续保留参数化查询、全部输入就绪、执行指纹、冲突阻断、列表选择和级联收敛行为。
- 从旧版完整 SQL 规则升级时，必须先备份数据库，再按相同数据来源安全整理查询对象：兼容的规则合并公共查询和输出映射；运行规则 `Guid` 必须转移到对应入口。
- 无法确认可以安全拆分的复杂 SQL、CTE、聚合或其他结构不得强行合并，必须作为“高级完整 SQL”入口原样保留，确保升级前后执行语义一致。
- 当前既有 9 条规则应整理为 5 个查询对象：患者基本信息、就诊信息、病案号与就诊号、医生信息、科室信息；仍保留 9 个查询入口。
- 旧入口“根据病案号取用户ID”必须更名为“根据病案号取就诊号”，其实际输出仍为就诊号元素。

### 5.1 参数化 SQL 编辑器

- 公共 SQL 编辑器和高级完整 SQL 编辑器双击字段时，下划线必须视为字段名的一部分。例如双击 `PATIENT_ID_NUMBER` 的任意一段，应选中完整字段，而不是只选中某个单词。
- 字母、数字、下划线、`$` 和 `#` 均按 SQL 标识符字符处理。

### 5.2 输出列映射

- “结果列名”必须使用下拉框，下拉内容来自查询对象公共 SQL 最外层 `SELECT` 的结果列或别名。
- 解析结果必须支持普通字段、限定字段、显式 `AS` 别名、隐式别名、函数表达式别名、引号/方括号别名和 CTE 后的最终 `SELECT`；通配符不作为可映射列展示。
- “写入元素”使用全局元素下拉框。同一查询对象中，已经被其他映射行使用的元素不得再次出现在新行选项中；当前行已经选中的值必须保留可见。公共映射由该对象的所有入口共享。
- 打开或切换规则时，已有映射必须立即显示当前“结果列名”和“写入元素”；展开下拉框必须显示可选内容，不能因为页面包装层与内部配置上下文不同而出现空白。
- 输出映射表保持紧凑，当前基准总宽度为 520px，不应无意义占满整页。
- SQL 查询对象页左侧对象列表宽度固定为 202.5px（原 270px 的四分之三），右侧编辑区使用释放出的宽度；第 3 步输出映射表仍保持 520px，只随右侧编辑区整体左移，不横向拉长。
- 第 5 步连接测试区使用普通卡片底色，不使用黄色底色。
- 左侧查询对象列表在窄栏布局下仍保持清晰可读；对象名称和入口数量字体相对上一版各增大 1px。
- 第 4 步“查询入口”的“筛选条件不写 WHERE、排序不写 ORDER BY”等填写提示统一放在步骤标题下方，不占用列标题；列标题保持单行，筛选条件列优先获得更宽的编辑空间。
- 映射较多时，鼠标滚轮必须优先滚动第三步的局部列表；只有局部列表已经到顶并继续向上，或已经到底并继续向下时，才把滚动交给外层页面。

### 5.3 规则测试参数

- 测试参数必须按查询入口固定运行 ID 自动保存，切换入口或后续修改 SQL 时能够复用仍然同名的参数值。
- 测试参数必须使用当前 Windows 用户范围的 DPAPI 加密，不得写入日志、规则导出包或普通配置快照。
- 删除查询入口或查询对象时，应清除相关入口已保存的测试参数内容。
- 测试查询结果仍只在内存中预览，不得持久化。

### 5.4 规则包导入与导出

- 导出规则包时，必须导出当前编辑区的全部查询对象、查询入口及其可执行规则，以及这些入口通过 SQL 参数占位符或输出映射实际引用的全局元素并集；未被规则引用的本地元素不得进入规则包。
- 元素定义必须保留固定 `Guid`、全局元素名/key、中文名称、数据类型、是否日期、角色、分组、显示顺序、宽度、是否可人工输入、敏感标记和校验规则等完整配置。
- 导入新版规则包时，查询对象和入口替换当前编辑区的查询配置；全局元素按下列规则合并，不能清空无关本地元素：
  - 固定 `Guid` 相同：视为同一元素，允许 key 改名，并采用包内最新定义。
  - 固定 `Guid` 不同但 key 相同：复用本地固定 `Guid`，采用包内元素定义，避免产生重复 key。
  - 本地不存在相同 `Guid` 或 key：新增元素并保留包内固定 `Guid`。
  - 包内 `Guid` 与本地一个元素相同、但包内 key 又指向另一个本地元素时，属于身份冲突，必须停止整个导入并明确提示，不能部分写入。
- 与导入规则无关的本地元素必须保持原样。导入前必须显示将替换的规则数、元素新增数、更新数、复用数和保留的无关本地元素数，并经用户确认。
- 导入只修改当前编辑区，不得自动保存；用户点击“保存”并通过整体验证后，规则和元素必须作为同一份当前配置原子写入。
- 新版规则包必须带格式版本、查询对象、可执行规则及元素内容的 SHA-256 校验和，并校验对象与可执行规则一致、引用元素无缺失且无多余。旧版只包含规则或规则加元素的包仍可导入并自动整理为查询对象，但必须遵守对应的元素合并边界。
- 规则包无论新旧均不得包含服务器连接、用户名、密码、SQL 测试参数或患者数据。

## 6. 快捷查询页面

- 查询条件只使用一个“编辑/完成”按钮，不再单独保留加号按钮。
- “清空”和“开始查询”按钮必须紧邻“查询条件”标题右侧；查询运行期间出现的“取消查询”按钮与它们保持在同一操作区，不再放在页面右上角。
- 进入编辑状态后：
  - 展示所有尚未显示的全局元素，不受“是否可人工输入”限制。
  - 当前已显示的元素提供“移除”操作。
  - 添加和移除操作必须能在同一编辑状态完成。
- 元素能否加入查询条件，与元素能否人工输入是两件事：所有元素都可展示；`CanInput` 只控制输入框是否可编辑。
- 字段卡片的中文名称和全局元素名/key 必须上下排列，所有卡片保持一致；不显示分组名，也不显示“可输入/不可输入”文字。来源字段只显示产生该值的查询对象名称，不显示查询入口名称。
- 快捷查询页不显示顶部“查询链路”区域，查询条件及其余内容顺势上移；底部规则运行轨迹继续保留。
- 进入编辑状态后允许拖动已显示字段改变当前显示位置；点击“完成”后必须恢复为不可拖动状态。
- 可输入字段使用正常可编辑输入框；不可输入字段整体使用灰色只读样式，通过交互和视觉表达状态。
- 不可输入或 SQL 回填状态下的字段值必须允许用鼠标框选并复制；只读只限制修改，不得限制文本选择。
- 查询条件输入区域不必与标题文字左边缘对齐，应在不贴住状态条和卡片边框的前提下尽量向左扩展，并同时向右利用卡片宽度；输入值字号统一为 16px，减少身份证号等长内容被截断的情况。
- 字段卡片显示宽度为元素配置宽度的 `4/7`，当前最小宽度为 160px，以便每行容纳更多条件。
- 查询条件卡片采用紧凑纵向间距，只在内容上下保留必要留白，不以固定大高度占用页面空间。
- SQL 回填字段保持可选中文本并复制、双击或 F2 编辑、Enter 确认为人工值并重新查询、Esc 放弃编辑的交互；单击只聚焦字段，不得自动操作剪贴板。键盘 `Ctrl+C` 和右键菜单“复制”必须走同一条受保护复制路径；剪贴板写入应在独立 STA 后台线程中限时重试，剪贴板被占用或复制超时时只能提示重试，不能阻塞界面、卡死或导致进程退出。
- Enter 触发的异步查询异常不得逃逸到 WPF UI 线程；意外失败时必须恢复可操作状态并显示可重试提示，不能让进程闪退。
- 人工字段按 Enter 时，必须取消旧运行，并用当前人工值开始一轮新查询。
- 单条规则返回 1 行时自动选择；返回多行时等待用户选择后继续级联。
- 同一元素出现不同非空值时必须显示冲突并阻断该元素下游，不能静默覆盖。
- 点击查询条件的“完成”后，必须持久化当前显示的元素集合及排列顺序；切换页面或重新启动应用后均按该布局恢复。
- 查询条件布局只允许保存全局元素固定 `Guid` 和顺序，不得保存患者输入值、SQL 回填值或查询结果；已删除元素的旧布局项应自动忽略。
- 在当前配置没有变化时，切换到其他页面再返回快捷查询，必须保留患者输入、SQL 回填值、查询结果、列表选择和规则运行轨迹；只有用户主动清空、开始新查询，或当前配置确实变化时才重建查询状态。
- 查询结果表格按实际结果列宽紧凑展示，在最后一个结果列结束，不得向右生成大面积空白表格区域。
- 快捷查询页面不再提供“运行诊断”展开区，也不显示内部元素；只保留规则运行轨迹。诊断日志入口统一放在“关于”页。

### 6.1 嵌套滚动统一规则

- 所有存在外层页面滚动条和内层列表、表格或编辑器滚动条的页面，必须采用相同边界传递逻辑。
- 鼠标位于内层可滚动区域时，只要该区域在当前方向仍可滚动，滚轮就只作用于内层。
- 内层到顶后继续向上，或到底后继续向下，滚轮才传递给下一层可滚动容器，最终传递给整页。
- 下拉弹层打开时，滚轮优先作用于下拉选项；下拉列表到达滚动边界后再把同方向滚动传递给所在的内层表格或外层页面，关闭后恢复所在页面的正常滚动关系。
- 下拉框打开期间，所在表格或页面发生滚动时，弹层必须持续跟随并贴合当前下拉单元格，不能悬停在打开时的屏幕位置。
- 仅把鼠标指针从单元格移动进下拉弹层不得改变下拉列表的滚动位置；列表只响应鼠标滚轮、键盘或用户主动拖动滚动条。

## 7. 元素配置与主工作区界面

- 主窗口默认宽度为 1200px；按默认查询卡片 160px 宽度和 16px 间距计算，快捷查询页面单行必须稳定显示 5 个条件卡片，第 6 个条件自动换行。窗口仍允许用户按需缩放，最小宽度保持 1100px。
- 元素配置表格正文必须垂直居中，并显示清晰的行列分隔线。
- 元素配置表格不显示“顺序”列。
- 元素配置表格不显示“分组”和“校验正则（可选）”列，其他页面也不得展示这两个属性；底层字段可继续保留以兼容旧配置和规则包。
- 元素配置表格不提供点击列标题排序；元素顺序由当前配置自身决定，避免误以为排序会改变保存顺序。
- 元素配置表格不显示“敏感”列；底层敏感标记继续保留以兼容旧配置和规则包。
- 删除上述列后，其余列继续使用当前固定像素宽度，不得自动拉伸填满整个表格。
- 元素配置表格宽度必须按当前可见列重新计算，在最后一列结束，不保留额外空白列或大面积空白表格区域。
- 元素 key 对应的列名使用“全局元素”，不再使用“稳定 key”。
- 工作区当前菜单必须有突出但克制的选中底色，同时不得显示点击后产生的黑色焦点矩形边框。
- 工作区右上角不显示“患者值不落盘”字样。
- 下拉框沿用统一高度和垂直居中的应用样式；所有下拉框及下拉选项获得键盘焦点或选中时均不得显示额外的聚焦矩形边框，正常选中底色继续保留。
- 元素配置表格提供“是否日期”勾选列；该属性属于用户配置，升级时必须保留。
- “是否日期”等复选框必须使用双向即时绑定；点击“保存”时必须强制提交 DataGrid 当前编辑，以免最后一次勾选在切页或重启后丢失。
- 勾选“是否日期”后，该元素在人工输入、SQL 回填、下游 SQL 参数和列表结果中均按纯日期处理：
  - 统一显示为 `yyyy-MM-dd`。
  - 原值带 `00:00:00` 或其他时间部分时，舍弃时间，只保留年月日。
  - 支持 `yyyy-MM-dd`、斜杠/点号/中文年月日、紧凑八位数字以及年在前或年在后的常见排列。
  - 纯数字日期在月/日均不大于 12 时天然存在歧义，默认按“月-日-年”解释；数据库返回的原生 `DateTime` 不存在该歧义。

## 8. 查询引擎不可破坏行为

- 规则是否可执行只由其全部输入元素是否存在、非空且无冲突决定，不依赖规则配置顺序。
- 同一运行中，以“规则 ID + 规范化输入值”生成执行指纹；相同指纹只能执行一次，输入变化后允许重新执行。
- 双向规则或循环依赖必须能够稳定收敛，不能无限执行。
- 列表更换选中行时，必须撤销旧选择及依赖旧选择产生的派生值和执行结果，再继续调度。
- 单条 SQL 默认超时 15 秒、最多读取 500 行；一次查询运行最多执行 100 次规则。
- 取消旧查询后，旧查询结果不得覆盖新一轮查询状态。
- ODBC 驱动首次加载和首次建立连接不得阻塞界面线程；首次打开连接若发生瞬时 ODBC 失败，允许在尚未执行 SQL 的前提下自动重试一次，不能要求用户手工发起第二次查询。
- 连接设置中的 `SSL/TLS Server Name` 必须保留为可选项，用于引用 IRIS ODBC 客户端已配置的 TLS 定义；未使用 TLS 的环境可以留空，升级不得清除已有值。

## 9. 发布检查清单

每次生成新安装包或绿色版前必须完成：

1. 同步更新 `src/IrisQuickQuery.App/IrisQuickQuery.App.csproj` 与 `installer/IrisQuickQuery.iss` 的版本号。
2. 更新 README 中对应的安装包或绿色版文件名。
3. 运行 `./build.ps1 -BuildInstaller` 或 `./build.ps1 -BuildPortable`，不得跳过 Release 自动化测试。
4. 确认全部测试通过，尤其是升级恢复、隐私边界、SQL 安全和 WPF 冒烟测试。
5. 确认发布文件名与应用 `ProductVersion` 一致；安装包还必须确认安装器 `ProductVersion` 一致。
6. 记录发布文件路径、文件大小和 SHA-256。
7. 新增或修改长期产品行为时，补充对应自动化测试，并同步更新本文。
8. 绿色版必须检查压缩包内容，确认不包含 `config.db`、`Logs`、`Backups` 或其他用户数据。
